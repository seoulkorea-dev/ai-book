# 생성형 AI, 묻고 확인하고 활용하기: 작동 원리, 프롬프트, 검증, 책임

생성형 AI를 업무와 학습에 사용하는 사람을 위한 안내서입니다. 생성형 AI가 결과를 만드는 원리에서 시작해 프롬프트 작성, 결과 검증, 학습과 업무 활용, 도구 선택, 윤리와 조직 정책까지 다룹니다. 책 전체를 꿰는 원칙은 하나입니다. **AI는 초안을 만들고, 사람은 묻고 확인해 결정합니다.**

- 온라인으로 읽기: <https://seoulkorea-dev.github.io/genai-book/> (원본: <https://seoulkorea-dev.github.io/ai-book/>)
- 기준 일자: 책의 사실, 제품 정보, 법률 일정은 2026년 10월 31일을 기준으로 정리했습니다.

## 이 책을 만든 과정: 작성과 검수

이 책은 사람과 AI가 역할을 나눠 만들었습니다. 책에서 독자에게 권하는 방식, 곧 "AI가 초안을 만들고 사람이 확인해 결정한다"를 책을 만드는 과정에도 그대로 적용했습니다.

### 역할

| 역할 | 맡은 일 |
|---|---|
| 작가 | 책의 방향과 구성 결정, 장 제목과 핵심 문장 확정, 실무 경험과 예제 자료 제공, 모든 수정안의 채택 여부 결정, 최종 승인 |
| 작성(Claude) | 결정과 검수 지침에 따라 원고 수정, 빌드, 자동 검사, 저장소 반영 |
| 검수(Claude, 별도 대화) | 저장소를 읽어 원고를 검토하고 수정 지침과 반영 확인을 `reviews/`에 기록. 원고는 직접 고치지 않음 |

작성과 검수를 서로 다른 대화로 나눈 이유는 4장의 원칙 때문입니다. 결과를 만든 쪽이 스스로 확인하는 것은 검증이 아니므로, 원고를 고치는 쪽과 확인하는 쪽을 분리했습니다.

### 작업 순서

1. **결정**: 작가가 방향을 정하거나, 검수 의견 가운데 채택할 항목을 고릅니다.
2. **지침**: 검수가 수정 위치, 현재 문장, 수정 문장, 확인 기준을 표로 정리한 문서를 만듭니다.
3. **반영**: 작성이 원고를 고치고 빌드와 자동 검사를 통과시킨 뒤 저장소에 반영합니다.
4. **반영 확인**: 검수가 반영된 원고를 다시 읽어 지침대로 되었는지, 새 문제가 생기지 않았는지 확인합니다.
5. **기록**: 지침과 확인 결과를 `reviews/`에 날짜와 차수로 남깁니다. 결정을 바꿀 때는 이전 결정을 대체한다고 적습니다.

### 검수 방법

| 방법 | 내용 |
|---|---|
| 자동 검사 | 빌드, 그림과 표 번호, 원고 구조, 문체(어휘 치환, 100자 초과 문장, 이웃 문장 중복), 금지어, 링크 |
| 원문 정독 | 바뀐 문장을 앞뒤 문장과 함께 읽어 연결, 중복, 위치를 확인 |
| 사실 대조 | 수치, 날짜, 판결, 보고서는 1차 출처(원문, 공식 문서)로 확인. 확인하지 못한 사실은 그렇다고 밝힘 |
| 반영 전후 대조 | 문장을 고친 뒤 숫자와 고유명사가 바뀌지 않았는지 자동으로 비교 |
| 링크 전수 점검 | 모든 링크를 따라가, 도착한 절에서 해당 내용을 찾을 수 있는지와 본문에서 먼저 설명했는지 확인 |
| 화면 확인 | 그림을 브라우저로 그려 글자 겹침, 잘림, 흐름을 확인 |
| 독창성 점검 | 비교 대상 도서와 문장, 표, 예제, 그림, 구성의 유사도를 측정하고 겹치는 부분을 고쳐 씀 |
| 외부 검토 | 다른 검토 의견을 장별로 받아, 책의 원칙과 사실에 맞는 항목만 골라 반영 |

### 원고 원칙(요약)

- 사실은 원문을 확인한 뒤에만 씁니다. 바뀔 수 있는 정보는 확인 시점과 공식 안내를 함께 둡니다.
- 한 문장에는 하나의 생각을 담습니다. 꼭 필요하지 않은 부사와 접속어는 뺍니다.
- 다른 장으로 넘기는 링크는 본문에서 개념을 먼저 설명한 뒤, 그 내용이 있는 절로 겁니다.
- 프롬프트 예제는 "~해 줘" 말투로 쓰고, 실행 결과를 싣지 않은 경우는 "예상 결과"라고 밝힙니다.
- 자세한 규칙은 `STYLE.md`와 `CLAUDE.md`에 있습니다.

### AI 사용 표기

이 책의 8장이 권하는 방식대로 AI 사용 사실을 밝힙니다.

- 사용 도구: Claude(Anthropic)
- 사용 범위: 원고 초안과 수정, 문장 다듬기, 검수 지침과 반영 확인, 사실 확인을 위한 자료 검색, 유사도 측정, 빌드와 검사 도구 작성
- 사람이 한 일: 책의 방향과 구성, 장 제목과 핵심 주장, 실무 경험과 예제 자료, 모든 수정의 채택 여부와 최종 승인
- 확인 방법: 수치, 인용, 판결, 참고 자료는 원문과 공식 자료로 대조했고, 반영된 원고는 자동 검사와 정독으로 다시 확인했습니다.

## 자동 점검

원고를 고친 뒤 빌드하고, 커밋 전에 아래 명령을 실행합니다. 빌드는 만든 쪽 수를 출력하고, 다음 세 명령(금지어, 번호, 구조 검사)은 문제가 없으면 아무것도 출력하지 않습니다. `check_style.py`는 경고만 출력합니다.

```
python3 tools/build.py
grep -nEf lint/banned.txt index.html chapters/*.html appendix/*.html
python3 lint/check_numbers.py
python3 lint/check_structure.py
python3 lint/check_style.py
- `check_numbers.py`: 그림과 표 번호의 순서, 누락, 중복, 없는 번호 참조, 번호 뒤 조사
- `check_structure.py`: 캡션 형식, 절 제목과 그림, 표의 배치, 참고 자료 항목 id, 앵커 없는 장 링크, 용어 풀이 표제어의 본문 등장
- `check_style.py`: 어휘 치환 후보, 100자 초과 문장, 문장 첫머리 접속어, 이웃 문장 중복(종료 코드는 항상 0)

```
