## 1. 3장 "프롬프트 개선 요청" 추가(①)
**위치**: "자기 검토 요청" 절(id reverse) 바로 뒤, "생성 설정" 앞. h2 `프롬프트 개선 요청`
- "메타 프롬프팅"이라는 이름은 쓰지 않습니다. 학술 용어(Suzgun, Kalai 2024)는 한 모델이 여러 전문가 역할을 지휘하는 방법이라 이 절의 뜻과 다르고, 비교 책의 용어 사전과 교육 과정에도 있는 이름이기 때문입니다.

**본문**
```
프롬프트를 어떻게 수정해야 할지 모를 때는 AI에게 프롬프트 자체를 검토하게 합니다. 처음 프롬프트와 원하는 결과, 실제 결과의 문제를 함께 주고, 빠진 구성 요소와 수정한 프롬프트를 요청합니다. 수정한 프롬프트는 바로 사용하지 않고, 실행해 결과를 확인한 뒤 사용합니다.
```

**예제(코드 상자, 구체 예)**
```
아래 프롬프트로는 원하는 결과가 나오지 않았어.
원하는 결과: 새로 합류한 동료가 첫 주에 할 일을 날짜별 표로 정리한 안내문
실제 결과의 문제: 할 일이 문단으로 나열되고 날짜가 빠짐
1. 프롬프트 구성 요소 가운데 빠지거나 모호한 것을 찾아 줘.
2. 수정한 프롬프트를 보여 주고, 무엇을 변경했는지 한 줄씩 적어 줘.

<프롬프트>
새로 온 동료 안내문 작성해 줘.
</프롬프트>
```
**기대 결과 설명(본문 문단)**
```
기대할 수 있는 결과의 예에서는 맥락(읽을 사람과 첫 주의 일정), 출력 형식(날짜, 할 일, 담당자 열의 표), 제약 조건(분량)이 빠진 요소로 나오고, 이 세 요소를 갖춘 프롬프트가 제안됩니다. 사람은 제안된 프롬프트에 실제 일정과 담당자를 채운 뒤 실행해 결과를 확인합니다.
```
- 예제의 처음 프롬프트("새로 온 동료 안내문 작성해 줘.")는 일부러 보인 나쁜 예입니다.
- 이 절을 넣으면 3장 h2 순서는 … 기법 조합, 자기 검토 요청, 프롬프트 개선 요청, 생성 설정. 표 번호 변화 없음
