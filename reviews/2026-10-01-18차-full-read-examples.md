## 5. 사용자 결정 반영
### 5-1. 4장 기록 방법: 공지문과 비슷한 작업으로 교체
- 2장과 같은 공지문을 다시 쓰지 않고, 비슷한 종류의 작업(교육 안내문 정리)으로 1~3차 수정 기록을 보입니다.
- 본문 교체:
```
<h3 id="record">기록 방법</h3>
<p>프롬프트를 고칠 때마다 무엇을 바꿨고 결과가 어떻게 달라졌는지 기록합니다. 한 번에 한 요소만 바꾸고 기록하면, 결과가 좋아졌을 때 어느 수정 덕분인지 알 수 있습니다. 기록 항목(차수, 바꾼 요소, 결과, 다음에 할 일)은 이 책이 정한 형식입니다. 표 4-n은 교육 안내문을 표로 정리하는 프롬프트를 세 번 고친 기록의 예입니다.</p>
```
- 표 4-n(코드 상자 대신 표):

| 차수 | 바꾼 요소 | 결과 | 다음에 할 일 |
|---|---|---|---|
| 1 | 처음 요청 "이 교육 안내문 정리해 줘." | 문단으로 요약되어 신청 기한이 문장 속에 묻힘 | 출력 형식 지정 |
| 2 | 출력 형식: 항목, 내용, 기한 표 | 신청 기한, 교육일, 준비물이 표에 따로 정리됨 | 안내문에 없는 내용이 섞였는지 확인 |
| 3 | 제약 조건: 안내문에 없는 내용은 포함하지 마 | 안내문에 없던 "점심 제공" 항목이 사라짐 | 기록 종료 |
- 캡션: `표 4-n. 프롬프트 수정 기록 예` / `교육 안내문 정리 프롬프트를 세 번 고친 차수별 변경과 결과`
- 기존 코드 상자(날짜, 목적, 변경, 결과, 다음 과제)와 "시험 입력 5건 중 5건 형식 합격" 삭제

### 5-2. 8장 편향 점검: 구체 속성 예외 허용
- 규칙 추가(CLAUDE.md, STYLE.md 예제 규칙): `편향 점검처럼 속성 하나를 바꿔 비교하는 것이 방법인 예제는 성별, 나이 같은 속성을 적을 수 있다`
- 예제 교체:
```
[A] 남성 지원자의 자기소개서를 10점 만점으로 평가해 줘. (자기소개서 본문)
[B] 여성 지원자의 자기소개서를 10점 만점으로 평가해 줘. (같은 자기소개서 본문)
```
  마지막 안내 문장(합니다체)은 그대로 둡니다.

### 5-3. B 배제어 치환을 코드 상자 속 프롬프트에도 적용
- 앞서 정한 "코드 상자 속 프롬프트는 예외"를 **취소**합니다(사용자 결정).
