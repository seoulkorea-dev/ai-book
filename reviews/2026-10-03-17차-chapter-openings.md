# 여덟 장 첫 문단을 같은 논리 구조로 다시 쓰기

- 차수: 2026-10-03 17차 (Claude), 누적 71차
- 이전 문서: 2026-10-03-16차-ch05-summary.md
- 기준 커밋: 4a13804(70차 반영 a76834e 확인: 5장 요점 "스스로 생각해 답을 찾는 과정")

## 0. 배경과 사용자 결정
1. 사용자 지적: 1~4장 첫 문단은 "…을 다룹니다"처럼 해설하는 느낌이고, 5장은 갑자기 태도가 바뀐 주장문처럼 읽힘. 검수 확인 결과 장마다 첫 문단의 틀이 달랐음(1~3장은 범위 안내만, 5, 7, 8장은 주장만 있고 범위 안내가 없음)
2. 사용자가 문제를 다시 분석함: 지식의 압축(한 문장에 개념 여러 개), 인과 고리 생략, 한 문장 과부하. 해결: 1문장 1정보, 논리적 징검다리(연결 표현), 개념 구체화
3. 사용자가 구조를 정함: **작동 방식 → 한계 → 결과 → 행동 지침**의 4단계와, 연결 구조 "A가 아니라 B이다"(반전, 대비), "A하므로, B할수록 C하게 된다"(인과)
4. 범위 문장의 동사는 세 가지만 씀(사용자 결정)
   - **살펴봅니다**: 개념, 법령처럼 이미 정해진 내용을 설명할 때
   - **익힙니다**: 새로운 기술처럼 꼭 배워야 할 내용이 있을 때
   - **다룹니다**: 사실을 바탕으로 작가의 생각과 의지가 들어갈 때
5. 장별 동사: 1장 살펴봅니다, 2~4장 익힙니다, 5~7장 다룹니다(5장은 사용자 결정), 8장 살펴봅니다

## 1. 작성 원칙
- 각 장 첫 문단 = 4단계 문장 + 범위 문장 1개. 범위 문장의 주어는 모두 "이 장에서는"
- "그럴듯한 거짓말" 같은 표현은 쓰지 않음(AI는 의도를 갖고 속이지 않음). "그럴듯하지만 사실과 다른 문장"으로
- 모든 문장 100자 이하, B 등급 어휘 없음(검수 쪽 점검 완료)
- **작성 A 주의**: 설명용 번호(①~④)나 굵은 표시는 원고에 넣지 않습니다. 아래 코드 상자의 문장만 옮깁니다.

## 2. 장별 첫 문단(전체 교체, 요점 상자 앞 문단)

**Chapter 1**
```
생성형 AI는 학습한 데이터의 패턴을 바탕으로, 다음에 올 단어의 확률을 계산해 문장을 조합합니다. 다시 말해 AI는 사실을 확인해 답하는 것이 아니라, 가장 그럴듯한 단어를 이어 가는 것입니다. AI는 진위를 판단하지 않으므로, 학습 자료에 드문 내용일수록 그럴듯하지만 사실과 다른 문장을 만들기 쉽습니다. 따라서 AI의 결과는 그대로 받아들이지 말고, 작동 방식을 이해한 바탕에서 어디까지 믿을지 판단해야 합니다. 이 장에서는 생성형 AI가 결과를 만드는 방식과, 그 방식에서 비롯되는 강점과 약점을 살펴봅니다.
```

**Chapter 2**
```
모델은 사용자가 주는 입력 전체, 곧 프롬프트(Prompt)만 보고 작업합니다. 프롬프트는 목적, 역할, 맥락, 출력 형식, 제약 조건으로 구성되며, 이것을 프롬프트 구성 요소라고 합니다. 모델은 사용자의 상황을 아는 것이 아니라, 프롬프트에 적힌 만큼만 압니다. 적힌 정보가 적을수록 모델이 짐작으로 채우는 부분이 많아지므로, 결과가 의도에서 멀어지기 쉽습니다. 따라서 원하는 결과를 얻으려면 필요한 구성 요소를 갖춰 요청해야 합니다. 이 장에서는 구성 요소를 갖춰 요청하는 방법과, 모호한 표현을 구체화하고 입력 자료를 배치하는 방법을 익힙니다.
```
- 현재 첫 문단의 "질문 한 줄일 수도 있고 …", "모델은 프롬프트에 적힌 내용만으로 작업하므로 …" 문장은 위 문장으로 대체됨(내용은 2장 본문 "한 줄 요청을 작업 지시로"와 명확성 원칙에 있음)

**Chapter 3**
```
고급 프롬프트 기법은 예시를 보여 주거나, 단계를 나누거나, 도구를 사용하게 해서 모델의 작업 방식을 이끄는 방법입니다. 구성 요소는 무엇을 원하는지 알려 줄 뿐, 어떻게 처리해야 하는지까지 알려 주지는 않습니다. 분류 기준이 복잡하거나 계산과 판단이 섞일수록, 한 번의 지시로는 결과가 흔들리기 쉽습니다. 따라서 작업의 성격에 맞는 기법을 선택해 처리 방식까지 지정해야 합니다. 이 장에서는 예시 제공, 단계별 추론(Chain of Thought, CoT), 도구 사용, 작업 분할, 한국어 프롬프트, 자기 검토와 프롬프트 개선 요청, 생성 설정을 익힙니다.
```

**Chapter 4**
```
환각(Hallucination)은 AI가 사실이 아니거나 입력과 맞지 않는 내용을 사실처럼 생성하는 현상입니다. 환각은 오류처럼 보이는 것이 아니라, 정확한 답과 똑같이 자연스럽고 확신에 찬 문장으로 나타납니다. 겉보기로 구분되지 않으므로, 확인 없이 사용할수록 잘못된 사실이 결정과 문서에 그대로 퍼지게 됩니다. 따라서 결정에 사용하거나 외부에 공유할 핵심 사실은 원문과 대조하고, 서로 독립된 출처 두 곳 이상으로 교차 검증해야 합니다. 이 장에서는 환각을 알아보는 방법과, 평가 기준에 따라 결과를 개선하는 절차를 익힙니다.
```

**Chapter 5**
```
생성형 AI는 학습과 연구에서 개념 설명, 질문 답변, 연습 문제 출제, 요약, 자료 탐색을 돕는 보조 도구입니다. AI가 맡는 일은 정보를 정리하고 가공하는 것이지, 내용을 이해하고 판단하는 것이 아닙니다. 학습을 AI에게 맡길수록 정리된 답은 늘어나도, 지식은 자기 것으로 쌓이지 않게 됩니다. 따라서 AI의 설명은 생각을 돕는 데 사용하고, 사실과 출처는 논문이나 전문 서적 같은 원문으로 직접 확인해야 합니다. 이 장에서는 AI를 학습 도우미로 활용하는 방법과, AI가 제시한 사실과 출처를 원문으로 확인하는 방법을 다룹니다.
```
- 15차(69차)에서 첫 문단에 두었던 "AI가 만든 오류나 지어낸 출처를 같은 AI로 다시 확인하면 …" 문장은 첫 문단에서 빠집니다. 같은 내용이 5장 문헌 확인 절("AI가 만든 오류를 같은 AI에게 확인하게 하면 …")에 있는지 확인하고, 없으면 그 절 첫머리에 한 문장으로 옮깁니다.

**Chapter 6**
```
업무와 창작에서 생성형 AI는 초안, 정리, 분석, 아이디어를 맡습니다. AI는 결과가 어디에 사용되고 누구에게 영향을 주는지 판단하는 것이 아니라, 요청받은 내용을 만들 뿐입니다. 결과가 조직 밖으로 나가거나 다른 사람에게 영향을 줄수록, 그 책임은 결과를 보낸 사람에게 무겁게 남습니다. 따라서 AI가 초안을 만들더라도, 결과를 어디에 사용하고 무엇을 보낼지는 사람이 판단해야 합니다. 이 장에서는 맡기기 전에 정할 것, 업무 유형별 활용, 프로젝트 관리, 창작, 조직으로 넓히기의 순서로 이 원칙을 적용하는 방법을 다룹니다.
```

**Chapter 7**
```
생성형 AI 도구는 작업 목적, 데이터 정책, 연동 범위에 따라 용도가 갈립니다. 결과의 차이는 도구의 종류에서만 나는 것이 아니라, 도구를 다루는 사람의 역량에서도 납니다. 새 도구가 나올 때마다 옮겨 다니기만 하면, 한 도구를 깊이 다루는 역량은 쌓이기 어렵습니다. 따라서 기준에 맞는 도구를 선택한 뒤, 자신의 역량을 평가해 가장 낮은 것부터 연습해야 합니다. 이 장에서는 도구를 비교하고 선택하는 기준과, 활용 역량을 평가하고 연습하는 방법을 다룹니다.
```

**Chapter 8**
```
생성형 AI는 학습한 데이터를 바탕으로 결과물을 만들며, 그 과정에서 데이터에 담긴 편향(Bias), 개인정보, 저작물도 결과에 반영될 수 있습니다. AI는 결과물을 만들 뿐, 그 결과물에 대한 책임을 지는 것이 아닙니다. 책임은 결과물을 사용하고 제출한 사람과 조직에 남으므로, 점검 없이 사용할수록 법적, 윤리적 위험이 커지게 됩니다. 따라서 개인은 편향, 개인정보, 저작권의 위험을 점검하고, 조직은 사용 정책, 보안 대응, 규제 대응 체계를 갖춰야 합니다. 이 장에서는 개인이 점검할 여섯 영역과, 조직의 사용 정책, 보안, 에이전트 통제, 규제 일정을 살펴봅니다.
```
- 현재 첫 문단의 균형 문장("이 장의 점검은 AI 사용을 줄이자는 것이 아니라, 결과를 안심하고 사용할 수 있게 하는 절차입니다.")은 8장 다른 곳에 없으므로, 8장 마지막 마무리 문단("이 장의 점검과 정책은 Chapter 1의 원칙 …") **바로 앞**으로 옮깁니다. 이어지는 "점검은 편향, 개인정보, 권리, 투명성, 책임, 환경의 여섯 영역 …" 문장이 첫 문단 뒤에 있다면 그대로 둡니다.

## 3. 함께 확인할 것
- 1장 요점 상자 첫 줄("작동 방식을 알면 결과를 어디까지 신뢰할지 판단할 수 있습니다.")은 첫 문단 넷째 문장과 같은 뜻이나, 요점 상자는 요약 자리라 그대로 둠
- 4장 요점 상자 첫 줄(핵심 사실, 독립 출처 두 곳)도 같은 이유로 그대로 둠
- 각 장 첫 문단의 병기: 1장 없음(본문 첫 등장 병기는 그대로), 2장 프롬프트(Prompt), 3장 Chain of Thought, CoT, 4장 Hallucination, 8장 Bias. 병기 위치가 장 안의 첫 등장인지 반영 뒤 확인
- 이웃 문장 중복 lint(같은 절 단어 겹침 65%)가 첫 문단과 바로 뒤 문단 사이에서 걸리면 뒤 문단의 겹치는 문장을 정리

## 4. 반영 확인 기준
- 빌드와 lint 통과(100자 초과, 이웃 문장 중복 경고 없음)
- 여덟 장 첫 문단이 2절의 코드 상자 문장과 같음, 번호나 굵은 표시 없음
- 범위 문장 동사: 1, 8장 살펴봅니다 / 2, 3, 4장 익힙니다 / 5, 6, 7장 다룹니다
- 8장 균형 문장이 마무리 문단 앞으로 이동
