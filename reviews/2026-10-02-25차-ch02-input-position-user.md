## 0. 사용자 결정
- 2장 "입력 자료 위치" 본문을 사용자 문장으로 바꾸되, 사용자가 준 글쓰기 원칙(한 문장 한 생각, 군더더기 빼기, 주어와 서술어 호응)으로 다듬습니다. 긴 자료는 **앞에** 두고(구성 요소보다 먼저), 목적과 출력 형식을 끝에 한 번 더 적는 방식입니다.
- 22차(46차)에서 정한 "구성 요소 → 긴 자료 → 목적과 출력 형식 다시" 순서를 대체합니다. 표 2-8과 그림 2-1도 본문과 같은 순서로 바꿉니다.
- 이 순서에서는 구성 요소에 목적과 출력 형식이 이미 들어 있으므로, 끝에 다시 적는 것이 "한 번 더"로 성립합니다.

## 1. 본문 (사용자 문장을 사용자가 준 글쓰기 원칙으로 다듬음)
사용자가 함께 준 원칙: 한 문장에 하나의 생각만 담는다, 꼭 필요하지 않은 부사와 접속사는 뺀다, 주어와 서술어를 가깝게 두고 호응을 맞춘다.

**사용자 문장**
```
입력 자료는 길이를 기준으로 위치를 정합니다. 짧은 자료는 구성 요소 뒤에 배치하고, 긴 자료는 앞에 배치합니다. 다만, 긴 자료를 앞에 둘 경우 목적과 출력 형식을 끝에 한 번 더 강조해야 합니다. 지시 사항이 긴 입력의 중간에 위치하면 반영률이 떨어지기 때문입니다(Chapter 1). 그림 2-1에서 두 경우의 배치 순서를, 표 2-8에서 길이별 배치법과 그 이유를 확인할 수 있습니다.
```

**반영 문장(원칙 적용)**
```
입력 자료의 위치는 자료의 길이로 정합니다. 짧은 자료는 구성 요소 뒤에 둡니다. 긴 자료는 구성 요소 앞에 둡니다. 이때 목적과 출력 형식을 프롬프트 끝에 한 번 더 적습니다. 지시가 긴 입력의 중간에 놓이면 덜 반영되기 때문입니다(Chapter 1). 그림 2-1은 두 경우의 배치 순서입니다. 표 2-8은 길이별 배치와 그 이유입니다.
```

**바꾼 점**
| 원칙 | 사용자 문장 | 반영 문장 |
|---|---|---|
| 한 문장에 하나의 생각 | "짧은 자료는 …에 배치하고, 긴 자료는 앞에 배치합니다" | 짧은 자료와 긴 자료를 두 문장으로 나눔 |
| 한 문장에 하나의 생각 | "그림 2-1에서 …를, 표 2-8에서 …를 확인할 수 있습니다" | 그림과 표를 두 문장으로 나눔 |
| 불필요한 접속사 빼기 | "다만," | "이때"(긴 자료의 경우로 범위만 좁힘) |
| 주어와 서술어 호응 | "입력 자료는 … 위치를 정합니다"(입력 자료가 위치를 정하는 주체처럼 읽힘) | "입력 자료의 위치는 … 정합니다" |
| 짧고 담백하게 | "배치합니다", "강조해야 합니다", "지시 사항", "반영률이 떨어지기", "확인할 수 있습니다" | "둡니다", "적습니다", "지시", "덜 반영되기", "~입니다" |
| 뜻을 분명하게 | "긴 자료는 앞에" | "긴 자료는 구성 요소 앞에"(무엇의 앞인지 밝힘) |
- 내용(짧은 자료는 뒤, 긴 자료는 앞, 목적과 출력 형식은 끝에 한 번 더, 이유는 1장)은 사용자 문장과 같습니다.

## 2. 표 2-8(입력 자료 위치) 긴 자료 행
| 열 | 현재(22차) | 변경 |
|---|---|---|
| 배치 | 구성 요소 다음에 자료를 두고, 자료 뒤에 목적과 출력 형식을 다시 적음 | `자료를 앞에 둠. 목적과 출력 형식은 끝에 한 번 더 적음` |
| 이유 | 긴 입력에서는 앞과 끝의 정보가 더 강하게 반영되므로 지시를 자료 앞뒤에 둠(Chapter 1 컨텍스트 윈도) | `중간에 놓인 지시는 덜 반영됨(Chapter 1 컨텍스트 윈도)` |
- 짧은 자료 행은 그대로(구성 요소 뒤, 프롬프트 끝에 배치 / 지시를 먼저 읽고 자료를 처리)
- 열 이름이나 캡션에 "배치법"이 들어가야 하면 본문과 맞춰 캡션 설명을 `짧은 자료와 긴 자료의 배치법과 이유`로(작성 A 판단)
