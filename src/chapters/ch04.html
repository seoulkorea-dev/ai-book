Part 2 프롬프트 작성

Chapter 4 고급 프롬프트 기법과 자기 검토 요청

고급 프롬프트 기법은 5요소만으로 해결되지 않는 작업에서 결과 품질을 높이는 방법입니다. 이 장은 예시 제공, 단계별 추론, 도구 사용, 작업 분할, 한국어 프롬프트, 기법 조합, 자기 검토 요청을 다루고, 마지막에 생성 설정을 설명합니다.

  • Few-shot은 예시로 형식과 판단 기준을 전달합니다.
  • 단계별 추론(Chain of Thought)은 여러 단계의 계산과 논리가 필요한 문제에 사용합니다.
  • 결과를 받은 뒤 AI에게 근거, 반론, 조건 충족 여부를 점검하게 하면 사람이 확인할 지점이 드러납니다.

기법 요약

기법마다 효과가 있는 작업이 다르므로, 기법은 작업의 성격에 맞춰 선택합니다. 표 4-1은 이 장에서 다루는 기법 8개의 방법, 적합한 작업, 기법을 처음 제안한 논문입니다.

Few-shot

Few-shot은 입력과 출력의 예시 몇 개를 프롬프트에 포함해 작업 방식을 보여 주는 기법입니다. 분류 기준이나 출력 형식을 말로 설명하기 어려울 때 예시가 그 역할을 대신합니다. 아래 예제는 감정 분류의 기준과 형식을 예시 세 개로 전달합니다.

다음 문장의 감정을 긍정, 부정, 중립 중 하나로 분류하십시오.

문장: 제품이 설명과 같고 품질도 좋습니다. / 분류: 긍정
문장: 설명서와 다른 부품이 왔습니다. / 분류: 부정
문장: 주문은 월요일에 했습니다. / 분류: 중립
문장: 포장이 찢어져 있었고 환불도 거절당했습니다. / 분류:

예시는 분류 기준과 출력 형식을 동시에 전달하므로, 예시의 구성이 결과를 좌우합니다. 예시를 선택할 때는 다음 원칙을 지킵니다.

  • 균형: 분류별로 고르게 포함합니다. 예시가 한쪽 분류에 몰리면 결과도 그쪽으로 몰립니다.
  • 단일 판단: 한 예시에는 한 가지 판단만 담습니다. 긍정과 부정이 섞인 문장은 기준을 흐립니다.
  • 형식 통일: 모든 예시를 같은 형식으로 작성합니다.
  • 실제 작업과 유사: 실제 작업과 비슷한 길이와 난이도로 만듭니다.
  • 순서 섞기: 같은 분류의 예시를 연달아 두지 않습니다. Zhao 외는 2021년 논문 「Calibrate Before Use」에서 예시의 순서와 마지막 예시의 답이 결과에 영향을 준다고 보고했습니다.

단계별 추론

단계별 추론은 답을 바로 내지 않고 중간 과정을 먼저 작성하게 하는 방법입니다. 모델은 앞에서 생성한 토큰을 바탕으로 다음 토큰을 만들기 때문에, 중간 과정을 먼저 생성하면 그 과정이 최종 답의 근거가 됩니다. 이 방법은 여러 단계를 거치는 계산과 논리 문제에서 정확도를 높입니다.

구조화된 단계별 추론

계산과 판단이 섞인 문제는 거칠 단계를 직접 지정합니다. "단계별로 생각하십시오"라는 지시만 적는 것보다 추론 순서를 통제할 수 있고, 사람도 결과를 단계별로 점검하기 쉽기 때문입니다.

두 마케팅 안 중 비용 대비 효과가 큰 안을 고르십시오.
A안: SNS 광고, 비용 500만 원, 예상 도달 10만 명
B안: 협업 콘텐츠, 비용 800만 원, 예상 도달 15만 명

다음 순서로 답하십시오.
1. 안별로 1인 도달 비용을 계산하십시오.
2. 계산에 반영되지 않은 고려 요소를 두 가지 적으십시오.
3. 1과 2를 근거로 한 안을 고르고 이유를 한 문장으로 쓰십시오.

추론 모델에서의 차이

추론 모델은 답하기 전에 추론 과정을 내부에서 수행하므로, 일반 모델과 사용 방법이 다릅니다. OpenAI는 추론 모델 안내에서 추론 모델에는 단계별로 생각하라는 지시를 따로 포함하지 않도록 안내했습니다. 추론 모델에는 목표와 제약 조건을 명확히 제시하고, 추론 과정은 모델에 맡깁니다.

최근에는 모델을 변경하지 않고 한 모델 안에서 추론량을 조절하는 방식이 사용됩니다. Anthropic은 Claude Opus 4.6에서 모델이 작업 난이도에 따라 추론량을 스스로 정하는 적응형 추론(adaptive thinking)을 도입했고, Claude Opus 4.7부터는 적응형 추론만 지원합니다. 추론량은 노력 수준(effort) 설정으로 조절합니다. 따라서 사용자는 모델 선택과 함께 추론 강도를 정합니다.

적용하지 않는 작업

단순 조회, 짧은 번역, 창작 초안처럼 추론 단계가 없는 작업에는 단계별 추론을 적용하지 않습니다. 정확도는 높아지지 않고 답변만 길어지기 때문입니다.

ReAct

ReAct는 추론(Reasoning)과 행동(Acting)을 번갈아 수행하는 방식입니다. 모델이 필요한 정보를 판단하고, 검색 같은 도구를 호출하고, 그 결과를 관찰해 다음 행동을 정하는 과정을 반복합니다(그림 4-1). 모델이 학습하지 않은 정보도 도구로 확인할 수 있어 최신 정보가 필요한 질문에 적합하며, AI 에이전트의 기본 동작 방식이기도 합니다. 자세한 내용은 위키 에이전트에서 다룹니다.

프롬프트 체이닝

프롬프트 체이닝은 작업을 여러 프롬프트로 나누고, 앞 단계의 결과를 다음 단계의 입력으로 사용하는 방법입니다. 긴 보고서로 발표 자료를 만드는 작업은 다음 세 단계로 나눌 수 있습니다.

  1. 긴 보고서를 장별로 나눠 요약합니다.
  2. 장별 요약을 모아 핵심 주장을 추립니다.
  3. 핵심 주장으로 발표 자료 목차를 만듭니다.

단계를 나누면 단계마다 결과를 확인할 수 있고, 오류가 있는 단계만 다시 실행하면 됩니다. 한 번의 프롬프트로 처리하면 어느 단계에서 오류가 생겼는지 찾기 어렵습니다.

한국어 프롬프트

한국어 프롬프트에는 문체, 높임법, 한국 기준, 용어 표기를 추가로 지정합니다. 지정하지 않으면 모델이 문체를 섞거나 해외 기준으로 답할 수 있습니다. 표 4-2는 요소별 지정 방법과 이유입니다.

영어 자료를 근거로 답하게 할 때는 자료를 원문 그대로 입력하고 답만 한국어로 요청합니다. 자료를 먼저 번역하면 번역 과정에서 생긴 오류가 답에 섞이기 때문입니다.

기법 조합

실제 작업에서는 기법을 하나씩 사용하기보다 조합해 사용합니다. 각 기법이 해결하는 문제가 다르기 때문입니다. 예를 들어 Few-shot은 형식을, 구분 기호는 자료와 지시의 분리를 담당합니다. 표 4-3은 작업별 조합 예제입니다.

자기 검토 요청

자기 검토 요청은 결과를 받은 뒤 AI에게 자기 결과를 다시 점검하게 하는 방법입니다. 모델이 자기 결과를 점검해도 오류가 모두 드러나지는 않으므로, 점검 결과는 사람이 확인할 목록으로 사용합니다. 요청 방식은 세 가지입니다.

  • 근거 요구: "위 답의 각 주장에 대해 근거가 된 원문 문장을 인용하십시오. 근거가 없는 주장은 표시하십시오."
  • 반론 요구: "위 결론에 반대하는 입장에서 가장 강한 반론 세 가지를 작성하십시오."
  • 조건 확인: "처음에 제시한 제약 조건을 하나씩 나열하고, 결과가 각 조건을 지켰는지 표로 적으십시오."

생성 설정

모델은 다음 토큰을 확률에 따라 선택하며, API와 일부 개발 도구에서는 선택 방식을 설정으로 조절할 수 있습니다. 대화형 제품은 대부분 이 설정을 화면에 표시하지 않으므로, 이 절은 API를 사용하는 독자를 위한 내용입니다. 표 4-4는 주요 설정 세 가지의 의미와 사용 예제입니다.

top_p 방식은 Holtzman 외가 2019년 논문 「The Curious Case of Neural Text Degeneration」에서 제안했습니다. temperature와 top_p는 둘 다 선택의 다양성을 조절하므로 둘 중 하나만 조정합니다.

최근 모델은 이 설정을 지원하지 않기도 합니다. Anthropic은 Claude Opus 4.7부터 temperature, top_p, top_k에 기본값이 아닌 값을 보내면 400 오류를 반환하고, 이 설정 대신 프롬프트로 동작을 조정하도록 안내합니다. 따라서 설정을 사용하기 전에 해당 모델의 개발 문서에서 지원 여부를 확인합니다.
